# Operations

- `/health/live` checks process life; `/health/ready` checks SQL and draining. One default worker loop claims durable rows. Each claim has a 90-second lease and ten-second heartbeat. Units are unique by job/unit; settlement is exclusive. Expired leases settle retained successful units and release remaining reservations. A heartbeat renewed before reconciliation is checked again under the settlement lock. An expired worker cannot publish a late unit.
- Cancellation records intent. Queued work is settled immediately only while still queued; a running worker checks before new children and settles started units. Revoked connections stop new scheduling. Cap edits apply to new reservations; accepted budgets remain reserved.
- Queue age: inspect wd_jobs queued created_at. Running leases: wd_jobs lease_until. Durable dispatch state: wd_outbox. No external queue publication is required. A failed claim leaves its transaction rolled back and work available.
- Financial reconciliation: wallet reserved equals SUM(ceiling) for queued/running jobs. Wallet balance equals SUM(grant,purchase,settle,refund,adjustment credits). Reserve/release ledger rows describe holds and never also debit posted balance. Check unique settlement/unit/webhook references. Never rewrite the append-only ledger to repair an error; use a compensating operator transaction and an auditable reference.
- Cost/trace: wd_units contains integer cost estimates and per-unit metrics; wd_jobs has cumulative cost and its internal ceiling. Extraction records measured and estimated tokens. Do not expose internal costs through public capabilities. Provider invoices, failed HTTP/search costs, browser CPU/transfer, storage and payment fee reconciliation still need production instrumentation before economic claims.
- Kill switch: WEB_DATA_KILL_SWITCH=true stops new reservations. Drain with SIGTERM: stop claims, finish the current bounded unit/job, release/settle and close SQL. If forcibly stopped, stale-lease reconciliation completes on restart. Provider/domain kill-switch granularity and a metrics exporter are pending.
- Retention: each worker cycle nulls expired result bodies, removes expired caches/quotes/OAuth state, and deletes terminal job metadata older than 30 days. Financial rows remain. Owner DELETE /v1/results/:id removes retained content and invalidates that tenant's cache. Long-running deployments must monitor cleanup lag. Database backups can retain content until their published backup-retention window; do not promise instant deletion from historical backups.
- Backup: use managed PITR plus encrypted daily pg_dump, store separately from the host, and test pg_restore into an isolated database with provider access disabled. Reconcile wallet/ledger/active holds after restore before accepting traffic. Docker volume persistence alone is not a backup.
- Rollback: drain and disable new work, deploy the prior tested application image, retain schema/ledger, restore only after an explicit reconciliation plan. Never drop money tables or replay a purchase from a success URL. Keep the scanner deployment independently recoverable.
- Secrets: vault/environment injection only, separate sandbox and production settings, rotate control/API/provider secrets, revoke impacted connections. No content, bearer token or one-time key in logs. The legacy response logger excludes the new dashboard API. Use request/job/tenant IDs for incident correlation.
- Alerts and dashboards still required before paid release: queue age, worker saturation, attempts, browser fallback, provider spend, ledger mismatches, stale reservations, expiration lag, p50/p95, failed requests, signup abuse and auth anomalies.
