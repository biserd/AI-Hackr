NATIVE FIRECRAWL API

Use the tools you already know.

This deployment runs Firecrawl v2.11.162 and the official Firecrawl MCP server. API schemas, scraping, conversion, crawling and queue execution come from upstream.

REST and SDKs

Use your deployment origin as apiUrl. Send your operator-issued API key in Authorization: Bearer …. The key is checked at the gateway and is never sent to target websites.

POST /v2/scrape
POST /v2/map
POST /v2/crawl
GET /v2/crawl/:id
DELETE /v2/crawl/:id
POST /v2/batch/scrape
POST /v2/search · provider required
POST /v2/extract · LLM required

Upstream API reference ↗

MCP

Connect your MCP client to https://aihackr.com/mcp with the workspace bearer API key. The server reuses the official native tool implementations, schemas and transport. Only tools supported by the configured OSS deployment are exposed. Hosted OAuth linking is not enabled.

Deployment scope

One operator workspace; public target pages. Public signup, multi-tenant paid billing and OAuth linking are not yet enabled. Customer cookies/headers, browser actions and webhooks are rejected. Browser subresources rely on the upstream renderer’s protections; a public paid release still needs the full isolation, rate-limit and recovery audit.

Fire-engine, Agent, Interact, Alexandria, advanced anti-bot capabilities and screenshots are not included in the default OSS stack. Optional providers require operator credentials and independent validation. The self-hosted API is private, behind the authenticated gateway.

JavaScript
import Firecrawl from 'firecrawl';

const app = new Firecrawl({
  apiKey: process.env.AIHACKR_API_KEY,
  apiUrl: 'https://aihackr.com'
});

const page = await app.scrape(
  'https://example.com',
  { formats: ['markdown'] }
);

console.log(page.markdown);
